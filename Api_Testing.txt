//Auths used in API testing Postman
1. No Auth – No authentication is required to access the API.

2. Basic Auth – Uses a username and password to authenticate the API request.

3. Bearer Token – Sends an access token in the Authorization header as "Bearer <token>".

4. API Key – Uses a unique key to identify and authorize the API request.

5. OAuth 1.0 –  Uses signatures to authenticate API requests.

6. OAuth 2.0 – Uses access tokens to authorize API requests.

7. JWT (JSON Web Token) – Uses a signed JWT token to securely authenticate API requests.

8. Digest Auth – Uses a username, password, and hashed challenge-response mechanism for authentication.

9. AWS Signature – Uses AWS access key, secret key, and request signature to authenticate AWS API requests.

11. NTLM Authentication – Uses Windows-based credentials for authentication, commonly used in Microsoft environments.

HTTP Response Codes:

200 - OK
Request successful.

201 - Created
New resource successfully created.

202 - Accepted
Request accepted for processing, but processing is not completed yet.

204 - No Content
Request successful, but there is no response body.

400 - Bad Request
Invalid request data or incorrect request format.

401 - Unauthorized
Authentication is required or authentication failed.

403 - Forbidden
User is authenticated but does not have permission.

404 - Not Found
Requested resource/API endpoint does not exist.

409 - Conflict
Request conflicts with the current state of the resource.

500 - Internal Server Error
Unexpected error occurred on the server.

501 - Not Implemented
Server does not support the requested functionality.

502 - Bad Gateway
Gateway/proxy received an invalid response from the upstream server.

503 - Service Unavailable
Server is temporarily unavailable./When Server is restarting

504 - Gateway Timeout
Gateway/proxy did not receive a response from the upstream server in time.

Q- How do you validate API data against the database?
First, I send the API request and capture the response. Then I use the relevant ID from the response to query the database.
API:
User ID = 101
Name = Ishwar

Database:
SELECT * FROM users WHERE id = 101;

Expected:
ID = 101
Name = Ishwar

Q- What is database testing in backend testing?
-> Database testing verifies whether data is correctly inserted, updated, deleted, and retrieved from the database. I also validate constraints, relationships, data types, duplicate records, and data consistency.

Q-How do you test an event-driven workflow?
-> In an event-driven system, one service produces an event and another service consumes it. I verify that the event is generated correctly, contains the expected data, reaches the consumer, and triggers the expected business action.

Q-What is Kafka and how would you test Kafka-based workflows?
Kafka is an event streaming platform used to send and consume messages between services.
Producer sends the correct event
Topic receives the event
Message contains correct data
Consumer receives the event
Consumer performs the expected action
Duplicate messages are handled correctly
Failed messages are handled properly

Q-What is data consistency
Data consistency means the same data should remain correct across different systems or layers.
API → Order Amount = ₹1000
Database → Order Amount = ₹1000
Event → Order Amount = ₹1000

Q-How do you handle negative testing for APIs?
-> I intentionally send invalid or unexpected data and verify that the API returns the correct status code and error message without corrupting backend data.
Missing required field
Invalid data type
Invalid ID
Invalid token
Expired token
Duplicate request
Invalid JSON
Boundary values

Q-How do you test API authentication and authorization?
->Valid token → 200
Invalid token → 401

No token → 401
Valid token + insufficient permission → 403
